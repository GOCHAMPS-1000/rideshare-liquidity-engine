# 🚗 Rideshare Supply-Liquidity Engine (v2)

Where does rideshare supply fail to meet demand, how much would a targeted driver incentive cost, and how would we prove it works?

Built on **NYC TLC High-Volume FHV trip records** (real Uber/Lyft trips). Product-analytics portfolio project: data audit → metrics → policy simulation → experiment design → PRD.

> **Status:** code, tests, docs complete. **Results section below is filled in from your own run** (see "Fill in your results").

## What's inside
| Layer | Where | What it shows |
|---|---|---|
| Data audit | `liquidity/quality.py` | Who is missing from the data and whether the cleaning cutoff matters |
| Metrics | `liquidity/metrics.py` | p50/p90 waits, long-wait share, excess-minutes Pareto, density effect, unit economics, WAV-unmet |
| Policy simulation | `liquidity/simulate.py` | How often the PRD rule fires, what it costs, break-even ride lift, threshold sweep |
| Experiment design | `liquidity/experiment.py` | Sample size, MDE, design effect, switchback power simulation + A/A check |
| SQL | `sql/*.sql` | DuckDB versions of the key queries |
| Tests | `tests/` | 18 tests with hand-checkable data |
| Docs | `docs/` | Setup, concepts, code walkthrough, PRD, experiment design, interview Q&A |


## Key design decisions
- **Full month, not a 50 k sample**: window-level analysis needs the volume.
- **Percentiles and long-wait share**, because riders experience tails, not means.
- **Proxy metric, honestly labelled**: the data has only completed trips, so true unfulfilled demand is unobservable.
- **Excess-minutes ranking**: severity × volume, with a Pareto view for prioritisation.
- **Simulation ≠ proof**: the rule replay estimates cost and frequency only; the causal claim needs a **switchback experiment** because a marketplace violates the independence assumption of a plain A/B test.
- **Every number in `reports/summary.md` is generated by code**, so the write-up cannot drift from the analysis.

## Limitations
Single month, single city · completed trips only (survivorship bias) · `on_scene_datetime` mostly absent for Lyft · fare/pay are approximations of platform economics · simulation holds driver behaviour fixed.
